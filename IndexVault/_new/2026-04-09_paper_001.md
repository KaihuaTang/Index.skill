# Omni-SimpleMem: Autoresearch-Guided Discovery of Lifelong Multimodal Agent Memory

> [!abstract] TL;DR
> 本文用自主研究流水线 AutoResearchClaw 自动发现了一个多模态终身记忆框架 Omni-SimpleMem。从朴素基线出发，流水线自主执行约50次实验，在 LoCoMo 上将 F1 提升 +411%（0.117→0.598），在 Mem-Gallery 上提升 +214%（0.254→0.797），达到 SOTA。关键发现是：最大收益来自 bug 修复、架构改变和 prompt 工程，而非超参调优——这超越了传统 AutoML 的能力边界。

## In My Own Words (用我自己的话)

这篇论文做了一件很有意思的事：它没有靠人类研究者手动设计记忆系统，而是让一个自主研究流水线（AutoResearchClaw）来"做研究"——自动提出假设、写代码、跑实验、分析结果、迭代改进。起点是一个只能处理文本的简单记忆框架 SimpleMem，终点是一个能处理文本/图像/音频/视频的完整多模态记忆系统。

核心洞察在于：**真正带来巨大性能提升的不是调参数，而是发现 bug、改架构、改 prompt**。比如最大的单次提升（+175%）来自发现 API 调用缺少一个 `response_format` 参数导致输出冗余 9 倍。这说明复杂 AI 系统的优化本质上需要"理解代码"和"跨组件推理"，不是在数值空间里搜索就够的。

最终发现的架构有三个核心设计：(1) 选择性摄入——用轻量感知编码器过滤冗余输入；(2) 统一表示——所有模态统一为"多模态原子单元"（MAU），元数据热存储 + 原始数据冷存储；(3) 渐进检索——金字塔式逐级展开（摘要→全文→原始内容），配合 FAISS 稠密检索 + BM25 稀疏检索的集合并集融合。

## Research Problem & Motivation (研究问题与动机)

- **问题**: AI Agent 在长时间运行中积累多模态经验（文本、图像、音频、视频），但缺乏有效的终身记忆系统来保留、组织和召回这些经验
- **已有方案的不足**: 
  - RAG 类方案（Lewis et al.）：存储膨胀 + 检索噪音随记忆增长恶化
  - 结构化记忆（MemGPT, Generative Agents）：仅处理文本，丢弃视觉/听觉信号
  - 所有方案都是手动研究周期的产物，研究者每天只能探索少量配置，组件间交互容易遗漏
- **本文的切入角度**: 用自主研究流水线代替人类研究者，系统性地搜索涵盖架构、检索策略、prompt 工程、数据管道的巨大设计空间

## Method (方法)

### Core Idea (核心思想)

将"设计记忆系统"本身视为一个可自动化的研究问题。AutoResearchClaw 流水线接收三个输入：(1) SimpleMem 代码库作为起点，(2) 两个 benchmark 的评估工具，(3) LLM API 访问权限。然后进入迭代循环：分析→假设→实现→评估→决策（proceed/iterate/pivot）。

### Architecture (架构)

![[2026-04-09_paper_001_05.png|600]]

架构分三个核心模块：

**选择性摄入 (Selective Ingestion)**：多模态输入 → 模态特定的新颖度检测器（视觉用 CLIP、音频用 VAD、文本用 Jaccard）→ 通过过滤的信号封装为 MAU

**MAU 存储 + 知识图谱**：MAU = $\langle s, \mathbf{e}, p, \tau, m, \boldsymbol{\ell} \rangle$（摘要、嵌入、原始数据指针、时间戳、模态、链接）。热存储放元数据/嵌入，冷存储放原始大文件。同时提取实体构建知识图谱（7类实体 + 7类关系）

**渐进检索 (Progressive Retrieval)**：
- 混合搜索：FAISS 稠密检索 $D(q)$ + BM25 稀疏检索 $K(q)$，采用集合并集融合（保留稠密排序 + 追加仅 BM25 命中项）
- 金字塔展开：Level 1 摘要（~10 token） → Level 2 全文（相似度 > $\theta$） → Level 3 原始内容（在 token 预算 $B$ 内贪心展开）
- 知识图谱增强：从查询提取种子实体 → $h$ 跳邻域扩展 → 距离衰减评分 $r_G(v) = \beta^{d(v, V_q)} \cdot \text{conf}(v)$

### Key Innovations (关键创新)

1. **Autoresearch 发现范式** - 用自主研究流水线而非人工迭代来设计复杂 AI 系统，证明 bug 修复 / 架构改变 / prompt 工程的贡献远超超参调优，这是传统 AutoML 做不到的
2. **集合并集融合 (Set-Union Merging)** - 自主发现：FAISS + BM25 结果的合并不应用分数重排序（会破坏语义排序），而应保留稠密排序后追加稀疏独有结果。这一反直觉发现通过消融实验得到验证
3. **MAU 两层存储架构** - 热/冷分离使检索只需在紧凑的元数据上操作，大文件按需惰性加载，同时支持 8 worker 并行查询（3.5× 吞吐提升）
4. **金字塔渐进检索** - 三级内容展开避免一次性加载所有内容到 LLM 上下文，在 token 预算约束下自适应调整上下文深度

### Key Formulas (关键公式)

混合检索的集合并集融合：

$$R(q) = D(q) \cup \{m \in K(q) \mid m \notin D(q)\}$$

知识图谱实体的距离衰减评分：

$$r_G(v) = \beta^{d(v, V_q)} \cdot \text{conf}(v)$$

其中 $d(v, V_q)$ 是到种子实体的最短路径距离，$\beta \in (0,1)$ 是衰减因子。

### Key Findings (关键发现)

- **Bug 修复是最大贡献者**（+175%）：API 调用缺少 `response_format` 参数导致 9× 冗余输出，这种"一行代码 bug"是人工调参无法发现的
- **架构改变**（+44%）和 **prompt 工程**（+188% 在特定类别）各自独立超过所有超参调优的累计贡献
- 返回**完整原始对话文本**而非 LLM 摘要可大幅提升 token-overlap F1（+53%），反直觉——传统上摘要被认为更高效
- Prompt 约束的**位置**（问题前 vs 问题后）比约束**内容**更重要
- 消融实验：金字塔展开（-17%）和 BM25 混合搜索（-14%）是最关键组件

**Efficiency (效率)**:

![[2026-04-09_paper_001_04.png|600]]

- 8 worker 并行下达到 5.81 queries/sec，比最快 baseline 快 3.5×
- 关键在于 FAISS 和 BM25 索引是只读的，天然支持并发查询

## Critical Analysis (批判性分析)

### Strengths (优势)

- **方法论创新**：将"研究过程本身"自动化，而非只自动化超参搜索，展示了 autoresearch 在复杂系统优化中的可行性
- **实验充分**：跨 5 个 LLM backbone 的全面评估，详细的消融研究和优化轨迹分析
- **发现分类学**：提出六类发现（bug 修复、架构、prompt、格式对齐、数据修复、超参），量化了各类的贡献占比
- **实用性强**：架构设计（MAU 热冷分离、金字塔检索）有清晰的工程价值

### Weaknesses (不足)

- **对 AutoResearchClaw 的依赖**：流水线本身是黑箱，其内部决策逻辑难以复现或迁移到其他领域
- **评估局限**：仅在两个 benchmark 上评估，且 dev subset 用于快速迭代可能引入过拟合风险（尽管最终在完整集上验证）
- **基线公平性**：部分基线（如 MemGPT、Claude-Mem）本质上是纯文本系统，在多模态 benchmark 上的比较不完全公平
- **成本未充分讨论**：~50 次实验 × LLM API 调用的总成本未明确报告

### What This Opens Up (开启的研究方向)

- **Autoresearch 作为通用系统优化方法**：论文识别了四个使记忆系统适合 autoresearch 的属性（标量评估、模块化架构、快速迭代、版本控制），可作为评估其他领域是否适合自主研究的框架
- **跨组件交互的自动诊断**：流水线发现的许多改进来自组件间的意外交互（如评估格式与输出格式不匹配），这暗示未来需要专门的"系统级调试"工具
- **记忆系统的 scaling 问题**：当记忆库增长到百万级 MAU 时，知识图谱的实体消解和图遍历的可扩展性有待验证
